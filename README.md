# PERRINN

PERRINN is a contributor collaboration app for profiles and contributor discovery, conversations, account settings, PRN contribution accounting and funding flows, and community information.

## What’s in the app

- **Profiles and Team** for finding people and viewing their contributions.
- **Chat** for conversations and community activity.
- **Account settings** for profile and account details.
- **PRN Contribution Credits** pages for contribution recognition, balances, transfers, time credits, and project funding.
- **Community information** and links to related resources.

The main client routes are `/home`, `/profile/:id`, `/team`, `/apps`, `/chat/:id`, `/settings`, `/login`, and `/buyPRN/:id`. The root route redirects to `/home`. The legacy `/directory` URL redirects to `/team`. Both desktop and mobile PERRINN brand controls open Home. The home dashboard uses a balanced shared-image grid with equal 4:3 image slots showing each image in full without cropping, transparent tiles, small rounded image corners and full-screen viewing, four upcoming events linking to conversations, an active funds list directly below Events, and ten recently active users in a compact two-column grid with only avatars and names, linking to profiles. Funds initially shows four entries ordered by days remaining, with Load more for additional entries; each opens its conversation. Fund amounts and days display rounded to whole numbers. Touch-device visitors outside standalone mode also see a subtle home-screen tip above the banner; dismissing it hides it for the current tab session. The PERRINN profile banner appears above the headline using the already-loaded profile image; unavailable or failed images are omitted. It adapts to available width without prototype navigation or manual resizing.

Signed-in Home shows a full-width mention list below the headline with up to three unread mentioned chats, chat images, one-line previews and relative times. The panel has no visible heading or chat count and retains an accessible “Mentioned you” label. When there are no unread mentions, the panel shows a compact, muted “You're all caught up.” line. It reuses the sidebar’s loaded conversations and read cursors (initially 30 chats; “Load more” expands the scope), and opens the existing chat route.

The sidebar separates chats according to their latest verified message. Chats with `isBackendMessage: true` appear in a separate list between the main conversation list and account controls: up to 15 chats, in a fixed 192px space for three rows before scrolling. The list has no visible heading or status text and keeps that space when empty, loading or unavailable. They do not contribute to unread dots, manual-flag summaries or Home mentions. Unflagged legacy records stay in the main list; no backfill is performed. Release the updated message creation/verification Functions and the new Firestore composite index before the client. Cloud Functions changes require the explicit explanation and approval described in [AGENTS.md](AGENTS.md).

Home event countdowns show days from 24 hours, hours from three hours, and hours plus minutes below three hours (only minutes below one hour). Days and standalone hours round to the nearest whole number; the detailed countdown rounds up to the next minute. The final minute shows “Starting now”, then “In progress” from the start time. The exact start date and time remain visible above the countdown.

Home also shows a compact event notice above the banner from one hour before an event starts until its scheduled end. It displays the earliest-starting active event and the nearest upcoming event within that hour, with “Starts in …”, “Starting now” in the final minute, and “In progress” from the start. Each notice opens the existing event conversation; joining remains available there from five minutes before the start. Dates and times use the viewer’s local timezone. The notice has no dismissal and disappears when an event ends or its cancellation reaches the verified feed. Events without valid start/end times or a conversation link are omitted from the notice. A local clock refreshes timing while Home is visible and on tab return, without additional Firestore reads. Loading or unavailable event data does not show a notice; the existing events panel retains its loading/error/empty feedback.

All pages, including prototypes, share a conversation sidebar with PERRINN, Team, Discover and Apps navigation. The sidebar uses a scrollable, single-line conversation list with icons, truncated subjects, unread/flag dots, chat options (Add flag / Remove flag) and Load more. The main profile feed retains its existing presentation. The account area below it shows Login when signed out, or a flat clickable row with avatar, name and PRN balance that opens your profile and wallet. User profile headers show Contribute funds before the PRN balance; Settings remain accessible from your profile page. Below 900px, use the header menu button to open navigation; Escape or the backdrop dismisses it, and page navigation closes it automatically. Prototype pages retain their own preview controls within the shared shell. Conversation links retain their existing route URLs.

The `/apps` page replaces the Apps popup with a responsive grid linking to 424 Nürburgring Telemetry, 424 Greenpower Telemetry, Google Drive (when the existing team public link is available), WhatsApp, YouTube, LinkedIn, GitHub and Prototyping. External links open in a new tab; telemetry and Prototyping open within the app. The listing reads the existing team profile through `UserInterfaceService` and introduces no new persisted data.

`/424-greenpower-telemetry` requires sign-in and shows live scalar channels and charts, plus Load history by UK calendar date. The app retains accepted OMNI uploads permanently in Firestore; setup, bounded test commands and the pending real-phone compatibility check are documented in [424 Greenpower Telemetry setup](#424-greenpower-telemetry). Its rules, indexes and ingestion Function require a separately authorized deployment before real data is sent.

## Technology

- Angular 21, TypeScript, and Angular CLI.
- Angular NgModules and the Angular Router.
- AngularFire compatibility APIs with Firebase Authentication, Cloud Firestore, Realtime Database, and Storage.
- Firebase Cloud Functions v2, written in JavaScript and configured for Node.js 20.
- Firebase Hosting, with the production client build output served from `dist/`.

## Get started

Install a Node.js and npm version supported by the Angular CLI and install the workspace dependencies:

```sh
npm install
```

Start the development server:

```sh
npm start
```

The app is served at `http://localhost:4200/`. The development configuration uses `src/environments/environment.dev.ts`.

## Configuration and secrets

The client Firebase web app configuration is selected through Angular environment files:

- `src/environments/environment.dev.ts` for local development.
- `src/environments/environment.prod.ts` for production builds.

Browser environment values are included in the client bundle and must be treated as public configuration, not secrets. Do not put service account credentials, payment provider keys, or other privileged values in client files. Cloud Functions read privileged integration credentials through Firebase Functions secrets. Keep those values in the project's approved secret management setup and never add them to this README or source control.

Charts offer numeric channels from the loaded day; selections missing from that day remain removable. Drafts stay local until Save, and saved choices apply to every signed-in viewer across Live and history. New channels stay available in the editor until explicitly selected after the first save. Before any configuration exists, all loaded channels remain visible. Hiding a channel never deletes stored uploads. Concurrent edits are checked by revision; a stale editor must be cancelled and reopened. Deploy Hosting and the admin-only Firestore write rules together to enable hosted editing.

Dates and chart times use `Europe/London`, including GMT/BST. The timeline uses **server receipt time**; source timestamps remain intact in the raw payload. Numeric display rounds to six decimal places, while storage preserves the original JSON. Plot rendering preserves per-bin minima/maxima; the full samples remain loaded and stored. See [data-model.md → Greenpower telemetry](data-model.md#greenpower-telemetry) for the contract, work budgets and deployment considerations.
