# PERRINN UI Specification

This is the design authority for new and rebuilt PERRINN components. It reflects the product direction established with the product owner and the existing Angular client. If existing UI or CSS conflicts with these rules, follow this specification for new work. Do not redesign unrelated legacy screens as part of a component change.

## Legacy CSS boundary

- Treat the existing global stylesheet and existing screens as legacy implementation, not as examples of the intended design. Reuse a rule only after confirming that it agrees with this specification.
- The legacy universal selector in `src/styles.css` applies `overflow: hidden` and a fixed `line-height: 21px` to all elements. Scoped component styles must reset those inherited global declarations where they clip text; for page headings, use `overflow: visible` and a suitable proportional line height (the existing prototype pattern is `:host h1, :host h2, :host h3 { overflow: visible; line-height: 1.35; }`).
- For new or rebuilt UI, follow this specification even when global CSS or nearby legacy UI conflicts with it. Keep new styling scoped to the relevant component or page where the existing Angular setup allows it.
- Follow the UI inspection and global CSS review workflow in [AGENTS.md](AGENTS.md) when a legacy rule blocks this specification.
- The approved Night Signal Dark rollout is a global stylesheet reconciliation. Migrate production colors to shared palette and semantic tokens, including color bindings in templates and services. Keep dynamic values dynamic, and retain component or page rules only where they express screen-specific behavior. Avoid unrelated layout or behavior changes during this rollout.

## Styling ownership and migration

- `src/styles.css` owns production colour tokens, the legacy base/reset, shared controls and unmigrated screen rules. Shell layout belongs in `src/app/app.component.css`; Home, Chat, Profile, Settings, Login, Team and Buy PRN presentation belongs in their respective component stylesheets.
- Keep shell viewport sizing, `#main_container` scroll ownership, sidebar and mobile drawer rules in the App component. Preserve `main_container` and `secondary_container` IDs: legacy pages use them for scrolling and chat positioning.
- Component styles own their typography, layout, responsive rules and states. Use inherited typography within each migrated component, with explicit icon-font exceptions. The global reset still applies to legacy screens; do not remove it as part of an isolated migration.
- Profile owns its sidebar embedding through `:host.sidebar-profile` and the compact conversation-list rules in `profile.component.css`. The shell owns the scroll region and row-height token; it must not reach into Profile through `::ng-deep`.
- Settings, Login, Team and Buy PRN retain their existing layouts and interactions during CSS ownership migration. Their local styles preserve legacy typography and states; this migration is not a screen redesign. Buy PRN owns its currency-selector layout, including its mobile breakpoint. Shared progress, control and table utilities remain global while other components consume them.
- Before moving global rules, inspect template and runtime consumers, preserve effective styles, then verify the scoped replacement and remove superseded rules. Shared classes still used across screens remain global until their consumers are migrated.
- Night Signal Dark is the approved production palette. `/prototypes/night-signal-dark` remains available for comparison with the original `/prototypes/night-signal` study. Keep the original study’s local palette values for comparison.

## Design character

- Refer to PERRINN people as the **team** and **contributors**. Do not label the team as a community.

- Participation is open and contributions are voluntary. Do not show membership badges, eligibility thresholds, paid participation gates or upgrade prompts. Present PRN as contribution records, with funding available independently of belonging.

- Make the interface understated, engineered and calm, with a balanced information hierarchy.
- Keep useful information visible and organized; avoid both overcrowding and unnecessary whitespace.
- Make intent and available actions clear through layout, hierarchy, familiar controls and concise labels. Avoid descriptions, instructions and repeated wording when the interface already makes the meaning obvious. Add explanatory text only when it provides necessary information, such as an unfamiliar action, a consequential choice or an error; preserve accessible names for controls.
- Default to the smallest useful amount of visible copy. Show actions, labels, units, data and navigation; let the interface explain itself. Do not add introductory descriptions, user guides, interaction instructions, repeated status messages or implementation diagnostics (sample counts, memory use, file paths, frame numbers) to routine screens unless explicitly requested. Keep essential errors and required setup conditional, and retain accessible names and keyboard support. For 424 Nürburgring Telemetry, preserve the compact connection actions, three-lap Session table and charts/navigation without explanatory or diagnostic blocks. Before delivering UI, remove copy that repeats what its controls or layout already communicate.
- Use a dark-mode language inspired by current ChatGPT: deep neutral backgrounds, subtly differentiated dark surfaces and light neutral typography. Keep cards and panels borderless by default.
- Use panels to group most sections, but distinguish them subtly. Keep spacing compact and functional.

- Do not brand or label user-facing product UI as AI-driven. Use neutral terms such as “Assistant” where a conversational assistant needs a label; do not add AI badges, headings, navigation labels, or promotional copy unless the user explicitly requests that branding.

## Colour

- Use the **Night Signal Dark** palette as the production colour direction. Its core tokens are:

  | Role | Token | Value |
  | --- | --- | --- |
  | Page background | `--color-page` | `#0B1118` |
  | Surface | `--color-surface` | `#17212C` |
  | Raised surface | `--color-raised` | `#263443` |
  | Border | `--color-border` | `#7A8CA0` |
  | Keyboard focus | `--color-focus` | `var(--color-text-secondary)` |
  | Primary text | `--color-text` | `#F4F6F8` |
  | Secondary text | `--color-text-secondary` | `#CBD4DE` |
  | Muted text | `--color-text-muted` | `#AAB7C5` |
  | Primary action accent | `--color-accent` | `#E5C477` |
  | Accent text | `--color-accent-ink` | `#2A2417` |
  | Selected surface | `--color-selected` | `#344552` |
  | Error text | `--color-danger-text` | `#FCA5A5` |

- Data comparison traces may use `--color-data-comparison` (`#56B4E9`, sky blue) alongside neutral silver and gold. Keep lap identities consistent across charts, overview and cursor readouts; use thin solid lines and reserve success/error colours for status and timing deltas.

- For translucent production colours, use `color-mix(in srgb, var(--color-…) N%, transparent)` so they follow the shared palette. Do not repeat palette RGB values. PWA theme and launch backgrounds in `src/index.html` and `src/manifest.json` mirror the page token; chart backgrounds read the surface token.
- Use the page, surface and raised tokens to distinguish the canvas, grouped content, and controls or nested emphasis. Use the focus token for keyboard outlines. Reserve the border token for controls, or states where a border materially improves clarity or accessibility.
- Use light neutral primary text, cool secondary text and muted text for clear hierarchy. Keep text readable; do not use muted text for essential content when contrast is insufficient.
- Use gold for primary actions and restrained emphasis. Keep green for success, use the selected-surface token for selected controls, and use restrained red for errors. Use `--color-danger` for error fills and `--color-danger-text` for readable error text. Do not use gold as the sole indication of status.
- Never use pure black as a page or component background. Avoid gradients, shadows, and unrelated saturated accents.
- Use restrained red for errors. Keep destructive actions neutral and make their consequence clear in the label and confirmation.
- Define shared production colour tokens in `src/styles.css` and use them in global rules and components where the style is genuinely shared. Legacy tokens remain for existing prototypes; production rules must use the Night Signal Dark and semantic tokens. Do not add palette hex values to individual component styles when a shared token represents the role.
- Existing `--bg-black` is pure black and conflicts with this specification; do not use it for new or migrated page backgrounds. Keep component-specific layout and one-off styling scoped to components when it is not a shared design rule.
- Keep accent color sparse. Avoid gradients and high-contrast decorative color treatments.

## Typography

- Use the shared `--font-family-ui` token in `src/styles.css`: `'Segoe UI', -apple-system, BlinkMacSystemFont, 'Helvetica Neue', sans-serif`. The document sets this family and the shared `--font-weight-body` token (medium 500); the universal reset inherits both so routed components, sidebar lists, forms and nested text use the same family. Component rules should reference the token rather than repeat the stack. Exclude Material Icons and Material Symbols from local text-family resets so their glyph fonts remain intact. Canvas charts must read the document font family for their titles, axes and legends because canvas text does not inherit CSS.
- Use the default typography scale below for all new and rebuilt UI, including prototypes. The explicitly scoped Home, Chat, telemetry chart and compact sidebar sizes below take precedence within their respective areas; use the default scale elsewhere:

  | Text role | Font size |
  | --- | --- |
  | Page headline | 23px |
  | Section heading | 17px |
  | Primary body text, names and row/event titles | 16px |
  | Supporting text, dates, durations, timestamps and loading/error/empty messages | 15px |
  | Minor labels, section kickers, hints and helper text | 14px |

- The shared fund summary row on Home, profiles and the funding page leads with the chat subject in 14px medium emphasis, followed by the distinct fund description in 14px secondary text. Omit duplicate descriptions and the legacy “add a description” placeholder; fall back to the description, then Fund, when the subject is missing. Show raised amount/target and status together in a wrapping 13px metadata row above a neutral 4px progress track. Keep the optional 48px conversation image, wrapping titles/descriptions and a keyboard-accessible conversation action named for the subject. Compact Chat leads with the fund description because its conversation title is already visible; Chat details shares the amounts/status and progress styling. Omit redundant Current Fund/Other Fund labels, percentage badges and decorative fund cards. Expired and cancelled funds use concise Ended/Cancelled status when history is requested. Home omits the funds panel when there are no active funds or further results; retain loading, error/retry and explicit Load more states.

- Production chat uses an approved compact chat scale: 18px chat title, 16px section headings, 14px messages/names/body text and 13px supporting text. Its event and fund summaries and details follow the same scale. Text-entry fields use 14px on desktop and retain 16px at mobile widths to avoid focus zoom; icon and touch-target sizes remain independent. This exception is scoped to Chat and its composer, message, flag, PRN manager, event and fund components.

- Compact sidebar labels use 14px. Keep icon dimensions independent of text sizes.
- Home uses an approved compact exception on desktop and mobile: 20px page headline, 16px section headings, 14px names and list titles, and 13px supporting text, controls and states. Recently active profile buttons show only 24px avatars and 14px names.
- Keep these sizes on mobile. Resolve limited space through wrapping, layout and spacing rather than shrinking text. Do not use 9–12px text for ordinary labels or information users need to read.
- Telemetry charts use an approved 13px exception on desktop and mobile for all chart text: channel names, current/cursor/lap values, X/Y ticks and axis controls, group labels, track-map states, and correlation plot titles, readings and canvas axes.
- Use the shared `--font-weight-body` token (medium 500) for body text, metadata, navigation and form controls, weight around 550 for row titles, and semibold around 600 for headings and emphasized labels. Set emphasis in scoped component styles; let nested text inherit the intended weight instead of resetting every descendant. Component-wide descendant rules must not override their own heading and emphasis weights; the global reset already supplies weight inheritance.
- Use proportional line heights: about 1.45 for body text and metadata, and 1.35 for headings. Let rows grow when names or titles wrap; avoid fixed heights that clip larger text. Keep compact numeric date blocks legible with enough space for both lines.
- Keep headings quietly distinct from body text through modest size and weight changes, not display styling.
- Use the same typeface for text and numbers. Emphasize important values through size and weight, not a separate monospace face.
- Keep text within the same line consistent in font size, weight, family, and style, including inline dates, durations, units, and metadata. Do not vary typography within a line for routine emphasis. Set nested inline elements to inherit these properties explicitly when legacy global styles override inheritance.
- Maintain readable contrast and concise labels. Use the default scale and its explicitly scoped exceptions as the reference, not older compact prototypes or legacy typography overrides. Apply it incrementally to the requested screen; do not restyle unrelated legacy pages.

## Layout & spacing

- Keep the app viewport, page origin and scroll regions stable when adding buttons, counters, status indicators or other conditional features. Use existing navigation/control rows and replace controls in place when their action changes; never insert a shell row that pushes the page down, shrinks its usable height or shifts its scroll position. Do not change page layouts or add empty placeholder space to prevent button movement. Controls must not wrap into an extra shell row or cover page actions. Verify appearance, updates and removal on desktop and mobile, including viewport-filling Chat and sticky telemetry navigation.
- Adapt content width and columns to the content. Use a readable maximum width for focused forms and detail views; allow data-heavy or workspace layouts to use more of the viewport when that improves scanning.
- Stack multi-column layouts into one column on mobile and keep key actions visible. On tablet, adapt to content and available space; retain columns only when they remain readable.
- Use distinct panels for most meaningful sections, separated through background contrast, spacing, and alignment. Avoid splitting a single task or closely related information across unnecessary panels.
- Keep spacing compact and functional. Use consistent gaps within a component and stronger separation between sections; do not add whitespace for decoration.
- Align related labels, values and actions. Choose grids, lists or tables according to the information rather than forcing one layout onto every data set.

## Components

- **User avatars:** use `app-user-avatar` for live user photos, including authors, recipients, profiles, Home and account controls. Missing, failed or known legacy placeholder photos fall back to up to two initials in a neutral circle, rendered with HTML/CSS. Keep valid stored photos and existing avatar dimensions. Do not generate fallback image assets or data URLs, upload replacements, or send names to an external avatar service. Conversation rows that use user photos share this component; attachment images and logos are separate content. Chat headers and details also use the shared avatar renderer with the conversation subject and stored conversation thumbnail, medium and original candidates; do not substitute the latest message author’s photo. A selected edit image previews in details only; undo or cancel restores the stored candidates. Preserve the 44px header and 80px details avatar dimensions.

- **Buttons:** use one filled gold primary style per task area, with accent ink for legible text. Secondary actions should have less visual weight. Destructive actions remain neutral; use clear wording and confirmation for consequential operations. Selected controls use the selected-surface token.
- **Inputs:** use dark filled fields with the surface or raised token, a subtle border, clear text and a restrained neutral focus outline. Keep labels and validation associated with their field.
- **Dropdowns:** shared native select sizing belongs in `src/styles.css`: automatic height, at least 44px touch height, responsive width, and reserved inline-end space for the arrow. Keep mobile select text at least 16px. Component padding overrides must retain arrow clearance; avoid fixed heights that clip text. Native selects suit short labels; use a wrapping picker for long metadata, following the History event selector. Preserve shell scroll ownership and fix custom-list clipping at the responsible container rather than removing global overflow boundaries.
- **Cards and panels:** use borderless surfaces by default, with the surface or raised token. Separate them through background contrast, spacing, and alignment. Do not add outline borders for decoration or routine grouping. Reserve borders for controls, focus indicators, or states where they materially improve clarity or accessibility. Do not use shadows or gradients.
- **Greenpower live discovery:** show the `Greenpower telemetry` link and green-dot `Live` badge below the Home heading only while today’s signed-in, server-confirmed phone telemetry is less than two minutes old. Remove the whole link when inactive, without reserving an empty row. In navigation, show `Telemetry · Live` beside Discover in the existing row while active. Both open `/424-greenpower-telemetry`; historical telemetry remains accessible through Apps. Keep the Home heading, Discover and all other controls visible and usable. The conditional Home link participates in the page’s content flow; live appearance/expiry must preserve the shell viewport and sidebar row geometry, including mobile and simultaneous radio return. Signed-out, cache-only, pending, failed and offline states show no Home telemetry link. Imported history never counts as live.

- **Greenpower legend emphasis:** Hovering or keyboard-focusing a trace legend quietly highlights that entry and fades other traces across the visible graphs. Overlay emphasis follows the same session across metrics and distinguishes paired channels where present. Preserve the selected trace’s normal colour and weight, cursor/zoom state and chart geometry; retain emphasis through gaps between legend entries and restore normal opacity only when leaving the legend. Touch scrolling and visibility toggles retain their existing behaviour.

- **Greenpower chart markers:** Each graph may show one enabled horizontal dashed reference marker with its numeric axis label in normal and overlay charts. Admins configure its checkbox and value beside that graph in Edit → Charts, independently of graph visibility; Save publishes it to every viewer and Cancel discards the draft. Retain values while disabled and keep controls/row dimensions stable on toggle. Existing markers remain enabled at their current values; other graphs start disabled. Use “Marker” in controls and accessible names, omit marker entries from legends, and retain measured comparison traces and session legends. Keep the marker and measured values visible through zoom and shared updates without clipping readings above or below it.

- **Greenpower race time:** display the `raceseconds` telemetry channel as Race time · min, converting seconds to minutes for plots while retaining raw values and saved channel IDs. Format scalar, live, cursor and overlay readouts as whole minutes and seconds, such as `23m 34s`, rounded to the nearest second; keep numeric chart axes in minutes.

- **Greenpower live zoom:** a zoom including the latest data keeps its selected start and extends its end as live samples arrive, across all ordinary charts. A zoom ending before the latest data stays fixed. Reaching the chart's right edge includes samples received during the drag. Reset restores the full live range; historical and overlay zooms retain their selected intervals.

- **Greenpower electrical analysis:** make Power · W and Energy · Wh selectable and reorderable in the shared chart editor for normal and overlay charts. Derive Power from total voltage and current, and Energy from power over time. Energy uses the amp-hour session reset eligibility, with a stable origin through zoom and cursor updates. Omit plots without valid data and do not add explanatory copy or extra controls. These plots reuse the existing chart frames and follow the saved chart selection and order.

- **Greenpower distance analysis:** make Distance travelled · mi selectable and reorderable in the shared chart editor. Integrate motor-derived speed only and reuse Energy's session reset and gap rules. Normal and elapsed-time overlay charts retain a stable origin through zoom and cursor changes; omit the plot without valid motor/gearing data. Reuse existing chart controls and layout without adding explanatory copy or rewriting saved layouts.

- **Greenpower voltage analysis:** show Voltage left and Voltage right on one shared volt axis, using solid/dashed traces and labelled readouts, alongside a separate Voltage diff plot. Keep both readouts in stable columns while cursor values update. Reuse shared zoom, cursor and lap interactions. The chart editor exposes Voltage left / right as one control and Voltage diff separately; both follow saved visibility and order. Each voltage channel remains independently available in Scalars.

- **Greenpower lap summary graphs:** make Lap time (seconds), Lap average speed · from motor (mph) and Lap average amps (A) independently selectable and reorderable in the shared chart editor; render them when selected and completed-lap data is available. Reuse the GPS/session lap boundaries and time-weighted averages from Lap list. Always calculate lap average speed from motor-derived speed; show no value when that signal or its full-lap coverage is unavailable, with no recorded-speed fallback. Mark the lap-table speed column From motor too. Plot one visible dot at each completed lap’s finish time and connect successive dots with straight lines. Incomplete laps and unavailable averages add no dot; the line joins the available completed values. Cursor readings use actual lap-finish points rather than interpolated summaries. Reuse shared cursor/zoom, normal plot sizes and overlay session colours/visibility controls. Overlay analysis uses each event’s saved track geometry; missing geometry or a track-area mismatch supplies no lap summaries. These graphs use the existing shared-view selection and order fields.

- **Greenpower calculated channel selection:** list all eleven client-calculated channels in Scalars, even when the loaded recording cannot supply a value. Show a dash for unavailable selected readings. In Charts, use one Vehicle speed / Motor-derived speed control and one Voltage left / right control for the paired graphs; expose Power, Energy, Distance travelled, Voltage diff, GPS lap and the three lap summary graphs individually. Calculated chart choices remain available without samples; omit selected graphs until valid data exists. Use the existing checkboxes, drag handles, keyboard ordering and Save/Cancel flow. Existing saved views are explicit allowlists: calculated charts previously inserted automatically now need to be selected and saved by an admin. Do not automatically rewrite shared settings or add controls to the page toolbar.

Keep raw channel names unmarked; the combined speed editor choice includes a calculated trace, while its recorded-speed heading/legend stays raw. Give the icon a Calculated in the UI tooltip and the label an accessible description. Preserve channel names, units, readouts, chart dimensions and toolbar geometry; add no badge backgrounds or explanatory page copy.

On RPM-only recordings, keep the selected Vehicle speed chart with the derived trace and show the recorded reading as unavailable. Overlay sessions keep their own colour, with Recorded/Motor-derived labels and a shared session visibility toggle. Use an event-only Wheel circumference · m field, initially 1.29; saving it updates the loaded event’s comparison. Lap speed averages exclusively use the motor-derived channel.

Keep scalar positions stable as metadata loads or changes. Show `—` when saved gearing is unavailable; never substitute the recorded sensor gear. See [data-model.md](data-model.md) for display derivation and metadata availability.

Its collapsible panel provides a session-preset dropdown, initially `2026 race sessions`, and a compact scrollable list with the same 14px colour-square visibility toggles as chart readings, retaining loaded data. Align races by elapsed time from each saved start. Keep one shared labelled colour key above the charts, using session names and stable colours when hidden or shown; chart cursor readings show the same names with wrapping text and a fixed value column. Overlay session labels show date, event and driver without the start time. Loaded battery dyno labels also append the maximum available computed Energy as `123.4 Wh`; omit it until computed samples are available. Do not display session numbers. Use 14px square visibility toggles with sharp corners beside chart session readings, filled with the session colour when visible and empty when hidden, with accessible Hide/Show names. The square is the only colour key in each chart reading and session-panel row; omit a separate trace-line swatch. Keep rows compact and show the full chart session list without an internal scroll region; Graph toggles hide traces across all charts while retaining reading rows and their Show controls. The main session-list toggles independently exclude a session from all graph traces, reading rows and the shared key; restore it from that list, preserving its previous graph-toggle state. Retain chart frames and plot height even when every session is excluded; rows reflow only on an explicit session-list toggle. Keep Hide/Show controls the same width, preserve chart zoom and cursor while toggling visibility, and show a concise empty state when all loaded sessions are hidden. Comparison traces may use distinct data hues, independent of status colours. Voltage pairs retain solid left/dashed right traces in each session's colour. While the underlying recording is Live, include its matching open Race or Battery dyno session automatically, even when historical pagination has not reached it. Order overlay session lists, shared keys and graph reading rows chronologically, with the live session always last, including after loading more history. Reuse loaded live data, mark that entry Live and update its elapsed trace and battery Wh label without resetting colour, visibility, zoom or cursor. Keep chart slots when live readings are temporarily unavailable and withhold incomplete consumption totals. Freeze the completed trace when its end is received. Closing the panel retains the comparison; Exit overlay restores the underlying dataset. Allow admins to edit shared chart visibility and order from the loaded comparison channels; keep scalar, event and session editing unavailable during comparison. Save applies the shared chart settings to overlay and ordinary views without changing track selection. Cancel or exiting comparison discards unsaved chart changes. Keep Track map and Lap list disabled during comparison. Overlay plot areas are 300px tall on desktop and mobile; ordinary plots remain 150px. Keep 44px toolbar action targets and one toolbar row; allow horizontal toolbar scrolling on the narrowest phones. Loading continues only through an explicit Load more action when a batch is incomplete.

Admin editing follows the active view: channel/event controls in Data, track selection and start/finish tools in Track map, and session editing in Lap list when a whole event is loaded. Keep the top Edit button in place. On mobile retain the 44px icon button; on desktop keep Edit/Done at the same width, preserving the action row and scroll position. Show the session form without shared-view tabs and return to the public session summary after save or cancel. Preserve drafts across view switches. - **Team Radio return:** while a joined radio is within its three-minute away window, show a compact neutral `Radio · m:ss` link beside Apps in the existing desktop navigation row and at the right of the existing mobile header. - **Greenpower number precision:** Apply the same measurement-based fixed decimal places to scalar, chart cursor, comparison, overlay and tooltip readouts: speed/current/voltage/temperature/throttle/altitude/acceleration/Ah 1; distance in miles 2; gear ratios and lap seconds 3; GPS coordinates 6; power (W), energy (Wh), RPM and lap counters 0. Recognise throttle by its channel name as well as its unit, including unitless `ActualThrtl`, `InputThrtl` and `actualthro` readings; recognise acceleration by its axis/channel name or acceleration unit and altitude by `alt`/`altitude`. Display acceleration in g, converting source m/s² (including unitless named acceleration channels) with 9.80665 m/s² per g; preserve raw recordings and source-unit channel IDs. Keep trailing zeros as values change (for example, 24.0 V → 23.9 V) and suppress negative zero. Unknown numeric channels use 3 decimals, with compact scientific notation for very small or large magnitudes. Preserve raw samples and full calculation precision. Chart axis tick precision follows its tick interval so zoomed ticks stay distinct; lap-table times retain milliseconds and current/speed averages retain one decimal. Chart marker labels show only the number using the same tick-step precision as the Y-axis labels, updating with zoom; keep units in the chart heading and accessible chart description. Do not round editable metadata or marker inputs.

- **Greenpower whole-event analysis:** Keep session annotations inside the existing plot area, with quiet solid start and dashed end markers. Show only session type and effective driver (session override, otherwise event default) when the visible interval is wide enough to fit the full label; reveal labels naturally on zoom. Clicking or keyboard-activating a session label zooms all graphs to its full saved time range and clears the cursor. Never show session numbers, a separate strip or a session key. Annotation appearance/removal must preserve chart height. At the top of Lap list, show the loaded whole event’s session list to every signed-in viewer, including sessions without laps. Each header shows the session type and effective driver, with UK-time ranges and the initial known gear ratio or subsequent ratio changes below. Only admins with the main Edit mode enabled see an Edit action on each session; opening it uses the existing session editor and preserves the recording. Group laps below under matching session/type/driver and UK-time ranges, keeping laps outside or across sessions separate. Start Lap 1 at each session’s start time and complete it at the first confirmed start/finish crossing; subsequent crossings increment the session counter. A start exactly on the line creates no zero-duration opening lap. Clip the final lap to the session end and mark it incomplete unless that end is a crossing. Keep the lap list, chart bands, cursor lap readouts and derived GPS lap channel consistent. Missing GPS coverage makes the opening interval incomplete rather than inventing a complete time or averages. Recompute after session edits or additional metadata loads; zoom and view switches never restart the count. Observations outside sessions retain their observed GPS index, with clipped fragments marked incomplete; overlapping session windows keep the original GPS analysis; without session metadata, preserve the recording-wide GPS count. Keep repeated lap numbers distinguishable by session in accessible zoom labels. Reuse loaded metadata across views and zoom; pending history choices never change these annotations.

- **Greenpower event metadata:** History offers one event per recorded UK day, with a Year filter that applies immediately on selection, without a Filter button. Align History labels and fields with consistent gaps; place Year beside Event on wider screens and stack them on mobile. History is event-only: show no session selector, session list or session pagination. Event choices use a wrapping picker so selected metadata and option labels remain readable on mobile; keep the arrow separate from the text and give choices at least 48px touch height. Bound the open list height and scroll it internally. Support arrow keys, Home/End, type-ahead, Enter/Space selection, Escape, outside dismissal and focus return; keep the native short Year selector padded clear of its chevron. Reuse the loaded event list without additional reads when opening or searching the picker. Show Load after an event is selected, without empty status rows between fields. Selecting an event attaches its metadata listener without fetching sessions or raw telemetry. Load retrieves the whole event and its first session metadata page (30 at a time); additional session pages belong to the loaded analysis, not History. A stable-width **Load** button starts the selected event only when pressed, closes the history picker and returns focus to Load history. Loading/error status remains visible beside the recording. Keep the previous recording, heading, cursor and zoom while choices change; identify the actual loaded event and time range independently of pending selection. ## Do / Don't

**Do**

- Use dark neutral surfaces, light neutral typography and borderless cards and panels separated through contrast, spacing, and alignment.
- Keep hierarchy clear, information balanced and spacing functional.
- Use neutral surfaces for selected states, green sparingly for success, and red for errors.
- Prefer inline feedback and content-appropriate data layouts.

**Don't**

- Use pure-black backgrounds, excessive colored elements or high-contrast decoration.
- Add gradients, shadows, animation or transitions.
- Make the interface generic SaaS, overly spacious, or needlessly dense.
- Create excessive panel subdivisions, inconsistent button styles, or arbitrary typography and colors.
- Treat legacy styling as intentional when it conflicts with these rules.

## Rules for new components

1. Read and follow `ui-spec.md` before building or rebuilding a component.
2. Reuse existing tokens and shared patterns where they fit this specification; where they conflict, follow this specification for new work.
3. Follow these typography, colour, spacing, layout, interaction and responsive rules. Existing global CSS is not an exception to the spec; use the legacy CSS boundary above when rules conflict.
4. Do not introduce a new visual pattern without a clear product reason.
5. Extend the PERRINN design system rather than creating a parallel one.
